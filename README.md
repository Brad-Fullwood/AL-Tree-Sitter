# AL Tree Sitter

> **Work in progress** — This grammar is under active development. Parse rates are high but edge cases remain. Contributions and bug reports are welcome.

A [tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for the **AL language** used in Microsoft Dynamics 365 Business Central development.

## Current Progress

- 660 keywords extracted dynamically from the VS Code AL extension
- **98%+ parse rate** against Microsoft's [BCApps](https://github.com/microsoft/BCApps) and [ALAppExtensions](https://github.com/microsoft/ALAppExtensions) repositories
- Full coverage of all AL object types, statements, expressions, and preprocessor directives
- Auto-generated `highlights.scm`, `indents.scm`, `outline.scm`, and `brackets.scm`

## Highlights

- **660 keywords** extracted dynamically from the official VS Code AL extension's TextMate grammar — zero hardcoded keyword strings
- **98%+ parse rate** against Microsoft's [BCApps](https://github.com/microsoft/BCApps) and [ALAppExtensions](https://github.com/microsoft/ALAppExtensions) repositories
- **Full AL syntax coverage** — all object types, statements, expressions, preprocessor directives, and quoted identifiers
- **Auto-generated queries** — `highlights.scm`, `indents.scm`, `outline.scm`, and `brackets.scm` produced alongside the grammar

## How It Works

The grammar is produced by a Rust **generator tool** (`al-gen`) that reads the TextMate grammar bundled with the Cursor/VS Code AL extension (`syntaxes/alsyntax.tmlanguage`), extracts every keyword and scope, and emits:

| Output | Description |
|--------|-------------|
| `grammar.js` | Tree-sitter grammar definition (1,188 lines) |
| `src/parser.c` | Main parser (~53K lines, auto-generated by `tree-sitter generate`) |
| `src/scanner.c` | External scanner — case-insensitive keyword/operator dispatch |
| `src/keywords.c` | Binary-search lookup table for all 660 keywords |
| `queries/highlights.scm` | Syntax highlighting queries mapped from TextMate scopes |
| `queries/indents.scm` | Auto-indentation rules |
| `queries/outline.scm` | Document symbol / breadcrumb queries |
| `queries/brackets.scm` | Bracket matching |

Because everything flows from the TextMate source, updating to a new AL language version is a single regeneration step.

## Prerequisites

- **Rust toolchain** (stable)
- **tree-sitter CLI** — `npm install -g tree-sitter-cli` or `cargo install tree-sitter-cli`
- **VS Code or Cursor AL extension** installed — the generator reads its TextMate grammar from `~/.cursor/extensions/ms-dynamics-smb.al-*/` or `~/.vscode/extensions/ms-dynamics-smb.al-*/`

## Build & Generate

```bash
# Generate grammar + run fixture tests
cd "AL Tree Sitter/generator"
cargo run --release

# Generate grammar + run fixture AND real-world repo tests
cargo run --release -- --test
```

The generator will:

1. Locate the VS Code/Cursor AL extension and read its TextMate grammar
2. Extract all 660 keywords, grouped by scope (control, operators, types, metadata, properties, etc.)
3. Generate `grammar.js`, `src/scanner.c`, `src/keywords.c`, and all `queries/*.scm` files
4. Run `tree-sitter generate` to produce `src/parser.c`
5. Compile the parser library
6. Run fixture tests against `tests/fixtures/`
7. *(with `--test`)* Clone/update Microsoft repos and parse all `.al` files, reporting success rate

## Testing

### Fixture Tests (always run)

Validates against hand-crafted AL samples in `tests/fixtures/`:

- `valid/` — Codeunits, tables, quoted identifiers, option types, preprocessor directives
- `invalid/` — Unbalanced begin/end, malformed syntax (should produce parse errors gracefully)

### Real-World Repository Tests (`--test` flag)

Configured in `tests/test_repos.toml`:

```toml
[[repo]]
name = "BCApps"
url = "https://github.com/microsoft/BCApps"
branch = "main"

[[repo]]
name = "ALAppExtensions"
url = "https://github.com/microsoft/ALAppExtensions"
branch = "main"
```

Clones each repo to `tests/.repos/`, parses every `.al` file, and reports per-repo parse rates. Target: **98%+** on production BC code.

## Grammar Coverage

### Object Types

codeunit, table, tableextension, page, pageextension, pagecustomization, report, reportextension, query, xmlport, interface, enum, enumextension, entitlement, permissionset, permissionsetextension, profile, controladdin, dotnet

### Statements

if/then/else, case, repeat/until, while/do, for/to/downto/do, foreach/in/do, begin/end blocks, exit, break, continue, with

### Expressions

Binary and unary operators, function/method calls, field access, array indexing, string/integer/decimal/date literals, option values

### Special Syntax

- **Preprocessor directives** — `#if`, `#else`, `#endif`, `#region`, `#endregion` with inactive code region handling
- **Quoted identifiers** — `"My Table Name"` parsed as identifiers, not strings
- **Attributes** — `[EventSubscriber(...)]`, `[NonDebuggable]`, etc.
- **Object modifiers** — `local`, `internal`, `protected`, `Extensible`

## Design Principles

1. **Zero hardcoded keywords** — All keywords extracted dynamically from the VS Code AL extension's TextMate grammar
2. **Tolerant parsing** — Graceful error recovery; handles preprocessor conditionals and permissive contexts
3. **High parse rate** — Targets 98%+ on real-world Microsoft BC production code
4. **Minimal manual maintenance** — Regeneration picks up new keywords and scopes automatically
5. **Case insensitive** — AL is case-insensitive; the external scanner handles this via normalized binary search
